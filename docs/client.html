The HTML client

The browser side has two directories. web-app/ holds the pages, presenters, CSS, and app logic. client/ is the API client: "the transport, the request context, the session, the bell, and the per-noun verbs" (ARCHITECTURE.md).

Build-time HTML composition

The README lists "Build-time HTML composition (shared layout + per-page content)". web-app/app/compose.ts reads PAGE_REGISTRY (web-app/app/page-registry.ts) and splits pages by layout:

const sidebarPages = Object.entries(PAGE_REGISTRY)
    .filter(([, entry]) => entry.layout === 'sidebar')

Each registry entry names its source, its CSS bundles, palette keywords, and a lazy loader:

ideas: {
    title: 'Ideas',
    layout: 'sidebar',
    inSidebarNav: true,
    sourceDir: 'ideas',
    sourceFile: 'index',
    icon: iconLightbulb,
    keywords: 'ideas list innovation',
    cssBundles: ['pages-ideas'],
    loader: () => import('../ideas/index.ts'),

web-app/ holds 34 app page templates (29 page files plus the 5 shared shell fragments) and 143 generated API-documentation pages under web-app/api-documentation/. The shared shell is a set of fragments in web-app/app/: components-layout.html, component-sidebar.html, component-top-bar.html, component-mobile-header.html, and component-mobile-sidebar.html. The page directories include ideas/, flows/, projects/, records/, workbox/, members/, identities/, organization/, billing/, design-system/, api-documentation/, auth/, landing/, and not-found/.

Pages and presenters

Every PAGE_REGISTRY page module exports init(). Presenters take data and return SafeHtml; they never touch the DOM, never fetch, never mutate. Editable views split a read presenter from an *Edit presenter; the page owns a PageState discriminated union ({kind: 'reading'} | {kind: 'editing', draft}).

ARCHITECTURE.md § Conventions. Presenters live in web-app/app/presenters/, for example state-display.ts and detail-field.ts.

Design system

"Colors are hsl(var(--token)) — never hex." Palette HSL lives in palette.css under one :root. Values live in web-app/app/styles/tokens.css and render at /design-system/. Variants ride data-tone (primary, success, warning, error, info, muted) and data-level (normal, warning, danger). Dialogs are native <dialog> elements driven by openDialog(id) and closeDialog(id) from dialog.ts. CSS file rules: "78-char max; no hex; no style="..." except dynamic custom properties" (DESIGN-SYSTEM.md).

This site uses those tokens: --background: var(--gray-900) (217 20% 15%), --card: var(--gray-800), --primary: 217 45% 60%, --accent-text: 48 80% 65%, and the font stacks --font-sans, --font-display, and --font-mono: 'IBM Plex Mono', 'Fira Code', monospace. The repo self-hosts Inter, IBM Plex Sans, and IBM Plex Mono as woff2 files in web-app/assets/. This site falls back to system fonts instead.

Command palette (Cmd+K)

web-app/app/command-palette.ts opens on the keystroke below. It searches ideas, projects, and members through the client (getIdeas, getProjects, getHumanMembers) and subscribes to their change feeds (subscribeIdeaChanges …):

return (e.metaKey || e.ctrlKey)
    && e.key === 'k';

The transport: client/http-facade.ts

return send(origin + '/api/' + resource, {
    method,
    credentials: 'same-origin',
    headers: requestHeaders(token, payload !== undefined, extra),
    ...

The facade binds fetch to a local because a property call "hands Chrome's fetch a receiver and throws 'Illegal invocation'". A collection GET is split with splitParts (shared/http-message/multipart.ts). "The client keeps each response whole, and pages and presenters read from the unit they were given."

Session and auth

  • Two credential modes (client/session-credentials.ts). Cookie-session mode is off by default: let cookieSession = false; ("Default is the localStorage pair for tests. server-core.ts enables this."). The shipped app turns it on with client.setCookieSession(true). The access token then lives in memory only and the refresh token in an HttpOnly cookie, "never localStorage". The 'fusion-angle:authorization' localStorage pair (client/session-storage-keys.ts) applies only to the default mode used by tests. Separately, 'fusion-angle:active-organization-id' persists the active org ("Boot re-exchanges a fresh org-scoped token from this id"), in line with "localStorage holds UI preferences only".
  • client/request-context.ts: "All concurrent 401s share ONE recovery". withAuthRecovery wraps a verb call with single-shot 401 recovery: one refresh and re-scope, and a second 401 clears the session.
  • client/session-refresh-mutex.ts: "One in-flight refresh POST. Concurrent 401s join this promise… Across tabs, navigator.locks serializes and a BroadcastChannel carries the winner's access token". The lock is 'fusion-refresh' and the channel is 'fusion-angle:refresh'.
  • Tenancy: "The org rides the VERIFIED token claim, never the path." Revocation bites at the next mint or refresh, or at ACCESS_TTL_SECONDS (15 min).

Broadcast channel (the bell)

client/broadcast-channel.ts is "The ONLY place BroadcastChannel is named". It uses CHANNEL_NAME = 'fusion-angle:data', and handlers "fan out from ONE native listener on the singleton channel". Because Deno ships its own BroadcastChannel, the module "key[s] on window", so it stays inert under deno test. A second browser "stays stale until navigation" (AGENTS.md).
