# TEST-PLAN mitigation — AA

- Section: AA
- Cases: AA-Obj
- Expected: All four objectives appear in the active list in the
  order created (each created via its own "+ Add objective" dialog
  open → fill Name/description → Add cycle).
- Observed: The Add Objective dialog's Name field does not clear
  between opens. Creating "Lower expenses" then immediately
  reopening the dialog to create "Increase incomes" produced a
  concatenated name, "Lower expensesIncrease incomes", because the
  field still held the prior value when the new text was typed in.
  Worked around via Edit after creation to reach the required
  4-objective end state; the objectives themselves persist
  correctly once corrected.
- Suspected layer: UI (dialog does not reset its form fields when
  reopened — likely missing a reset on dialog-open or dialog-close)

Possibly related in symptom (stale field state surviving a
dialog/form reopen or mode toggle) to `2026-08-25-B-B13.md`, though
the two live in different components (Organization page's Add
Objective dialog vs. the Auth page's Sign In/Sign Up form) and are
not confirmed to share a root cause.
