# SP-2 Tenancy — Implementation Plan

## Context — why this change

The fusion-ai platform is mid-transformation from a single-org demo
into a multi-tenant system. The roadmap spec
(`docs/superpowers/specs/2026-06-02-identity-auth-multitenancy.md`)
decomposes the work into SP-1..SP-6. SP-1 (identity core), SP-3
(token gate), SP-4 (authorization), and SP-5 (authentication) are
**done** on `master`. **SP-2 Tenancy is next on the critical path** —
the `5 → {2-facades, 6}` fork.

Today `organization` is a billing **singleton** (`store-singleton.ts`,
one row, id `'1'`) and **no entity carries an `organization_id`** —
every domain row is implicitly org-`'1'`. SP-2 promotes the singleton
into a tenant-root table, scopes the org-owned entities, and adds the
`/organizations/:organization_id/<entity>` facade routes that enforce
tenant isolation. The point is to forward-model real multi-tenancy at
the internal HTTP contract (`api/api.ts`) so the eventual server/
Postgres tier is a backing-store swap, not a contract rewrite.

This plan was designed against the Church of Code scripture (org
isolation is a **Security** boundary — Commandment II — a leak is a
broken covenant) and two parallel design passes that converged on the
same architecture. All load-bearing claims below were verified by
reading the source.

## Locked decisions (user-chosen this session — do not relitigate)

1. **Scope.** NOT-NULL `organization_id` on the org-owned domain
   entities **and** on `members` / `human_members` / `ai_members` /
   `role_grants`. Pure join tables derive org from their parent (no
   column — avoids Entangled Nouns). The identity/auth/infra spine
   stays global.
2. **Enforcement = "token-exchange bones now."** Facade routes mint an
   RFC-8693 org-scoped token (extending SP-5's `grantTokenExchange`)
   carrying a new `org` claim, and proxy an in-process sub-request to
   the flat root store. The root store reads org from the **verified
   token claim** (never a caller-controlled path/query) and enforces
   `entity.organization_id === org`, stamping it on writes. Adds an
   `org` claim to the token contract and an `organization` field to
   `Principal`, each **set once**.
3. **Backfill = re-seed only.** Mock + bootstrap seeds stamp
   `organization_id = DEFAULT_ORG` (`'1'`, a named constant). No
   in-place migration; pre-SP-2 snapshots fail import validation (the
   missing required column throws at the gate).

**Deviation recorded honestly:** the master spec (point 6) froze
"access token — no org claim," expecting org to ride the path. The
user's chosen mechanism overrides this: org rides a verified token
claim (the cleaner enforcement seam — one tamper-evident source, set
once). Record this deviation in the spec when SP-2 lands.

## Revision — multi-org membership (session 2026-06-04)

Two locked decisions are superseded by user choice this session,
after implementation surfaced that an identity must reach
MULTIPLE organizations (switch orgs without re-authenticating;
enumerate the orgs one can access).

1. **Membership is a join, not a column on `members`.** The
   original scope put NOT-NULL `organization_id` on `members` /
   `human_members` / `ai_members`, which capped an identity at
   one org (member.id === identity.id, keyed by id). Replaced
   by: those three tables STAY GLOBAL (member.id === identity.id
   preserved, one profile per identity); a new `memberships`
   join `(id, identity_id, organization_id, at)` records which
   orgs an identity belongs to. It is the org-scoped covenant —
   the source of "enumerate my orgs" and the exchange
   member-check — and the decorator scopes it. The per-org
   member LIST derives from `memberships(org)` joined to the
   global profiles. Per-org profiles are deferred (not required
   for switch/enumerate).
2. **The token embeds the accessible-org list.** Alongside the
   active `org` claim (set at exchange), the token carries
   `orgs: Id[]` — every org the identity belongs to, derived
   from `memberships` at mint time. `Principal` gains
   `organizations: Id[]` next to `organization`. This lets a
   client switch (re-exchange the org-agnostic refresh token)
   and enumerate without a round-trip. The list is a snapshot
   refreshed on each exchange; `GET /organizations` (scoped to
   the identity's orgs) stays the authoritative fresh source.

Unchanged: the org-owned domain cohorts (`ideas`, `projects`,
`flows`, `work_orders`, `records`, `record_attributes`,
`objectives`) and `role_grants` still take NOT-NULL
`organization_id` and are decorator-guarded; `role_grants`'s
`organization_id` now means the org the grant applies to.

## End-state global (non-org-scoped) URLs

Everything else lands under `/organizations/:organization_id/...`:
`/organizations` (directory) + `/organizations/:id` (tenant root); the
identity spine (`/identities[/:id]`, `/identity-pii`,
`/identity-credentials/:id`, `/identity-providers/:id`,
`/identity-tokens/:id`, `/identity-token-revocations/:id`,
`/authorization-codes/:id`); the auth front doors
(`/authentication/token`, `/authentication/authorize`); `/clients[/:id]`
(global app registry); `/snapshots/*` (whole-datastore ops).

## The three seams (the heart of the design)

### Seam 1 — the org-guard: an `EntityStore` decorator (insulation through adapters)

**Problem.** `handleRequest` (`api/api.ts:848`) reads only `pathname`
(line 852) and hands route handlers `(adapter, params, body)` — never
the token/Principal (the Principal is computed at
`authenticateRequest` 797-831 and **discarded** after authz). Threading
org through ~70 handler signatures + ~30 store methods is a giant
build-breaking change and scatters the guard (Sin of Internal Defense).

**Solution.** A new `OrgScopedEntityStore<T>` (in `api/store-org-scoped.ts`)
that implements the existing `EntityStore<T>` interface (`db.ts:69`) and
wraps a real store bound to one `org`:
- `getAll()` → filter `row.organization_id === org`
- `getById(id)` → if `row.organization_id !== org` throw
  `EntityNotFound` (a 404 — never a 403 that would confirm a foreign
  row exists)
- `put` / `putMany` → **stamp** `organization_id: org` onto the body
  (the store owns it; the caller can neither forge nor omit it)
- `delete` / cross-tenant `putMany` deletes → `getById` first to 404 a
  foreign-tenant id (no cross-org splice)

A factory `orgScopedAdapter(base, org)` (in `api/db-org-scoped.ts`)
returns a `DbAdapter` that wraps **only** the org-scoped stores and
passes the global spine + junction stores through **unwrapped**. The
scoped stores are **enumerated explicitly** (no reflective "wrap
everything with a column" — Premature Generalization avoided; the list
is short and reviewable).

```ts
// api/store-org-scoped.ts — the divorce point. Handlers + stores
// never learn org exists; the guard rides the SAME seam every store
// already crosses. When Postgres arrives this becomes WHERE
// organization_id = $org, callers unchanged.
export class OrgScopedEntityStore<T extends OrgScoped>
    implements EntityStore<T>
{
    readonly #inner: EntityStore<T>;
    readonly #org: Id;
    constructor(inner: EntityStore<T>, org: Id) {
        this.#inner = inner;
        this.#org = org;
    }
    async getAll(): Promise<T[]> {
        const rows = await this.#inner.getAll();
        return rows.filter(r => r.organization_id === this.#org);
    }
    async getById(id: string): Promise<T> {
        const row = await this.#inner.getById(id);
        if (row.organization_id !== this.#org) {
            throw new EntityNotFound('<org-scoped>', id);
        }
        return row;
    }
    async put(id: string, fields: Omit<T, 'id'>): Promise<T> {
        return this.#inner.put(id, {
            ...fields, organization_id: this.#org,
        } as Omit<T, 'id'>);
    }
    // putMany stamps each entry + 404s any foreign delete id;
    // delete 404s a foreign id before splicing.
}
```

**Wire-in (the only change to the ~70-handler dispatch).** In
`handleRequest`, after authz passes, derive the effective adapter once
from the verified Principal and dispatch against it:

```ts
const effective: DbAdapter =
    authResult.organization === undefined
        ? adapter
        : orgScopedAdapter(adapter, authResult.organization);
// switch(method) calls matched.get(effective, params) etc.
```

A flat (un-exchanged) token has no `org`, so `effective === adapter`
and **every existing test stays byte-identical** — the decorator is
inert for single-org callers. The auth gate itself
(`authenticate`/`authorize`) keeps reading the **base** adapter
(identity + roles are global concerns); only handler dispatch is
scoped.

`organization` is **set once** in two non-overlapping loci: on the
`Principal` (from the token's `org` claim in `principalFromToken`) and
on the guard (`#org` in the decorator constructor). Never a global.

### Seam 2 — the token-exchange + facade proxy (derive per-request)

**`org` claim on the token contract** (`api/access-token.ts`): add
`org?: Id` to `AccessTokenClaims` (mirroring the existing optional
`act?`, line 33) and to `MintInput`; spread it in `mintAccessToken`
(`...(input.org ? { org: input.org } : {})`); validate in
`hasClaimShape` (`org`, if present, must be a string); add
`organization?: Id` to `Principal` and set it in `principalFromToken`.
Optional everywhere → purely additive, no existing token changes shape.

**Extend `grantTokenExchange`** (`api/authentication.ts:170-201`) to
read `organization` from the body, verify the subject is a member of
that org (`members.some(m => m.id === subject && m.organization_id ===
org)` → else `403`, mint nothing — grant-first), and thread `org`
through `issueTokenPair` / `mintPair` exactly as `act` is threaded
today. The refresh token does **not** carry `org` (a tenant switch
must re-exchange, not ride a stale refresh).

**Facade routes resolved in the gate (no handler-signature change).**
Register `/organizations` + `/organizations/:id` (global directory +
tenant root) and the facade family `/organizations/:org/:entity` +
`/organizations/:org/:entity/:id`. Detect a facade in `handleRequest`
(`matched.segments[0] === 'organizations' && length >= 3`), then:
1. exchange the caller's bearer (subject == actor == caller; a
   self-delegation) with `organization: params[0]` → an org-scoped
   access token;
2. recursively `handleRequest` against the **flat** resource path with
   the org-scoped token. The recursion re-enters the gate, where
   `Principal.organization` is now set, so `effective` becomes the
   org-scoped adapter and the flat handler is fenced automatically.

This keeps the facade a **gate concern** (where the token + Principal
already live), not a handler concern. The query string is never used —
org rides the one verified vessel (avoids Scattered Context: org in two
places that could disagree).

### Seam 3 — noun-scoping (containment, never entanglement)

`organization_id` is a **containment fact** on entities, never on pure
join tables (a join holds only the joined identities + the moment of
union — a third relation welded on is Entangled Nouns, and the org
would be functionally dependent on the parents, inviting drift).

- **Gets the column** (locked + clear domain entities): `members`,
  `human_members`, `ai_members`, `role_grants`, `ideas`, `projects`,
  `flows`, `work_orders`, `records`, `record_attributes`, `objectives`.
- **No column — pure joins, derive from parent:** `idea_submissions`,
  `project_flows`, `flow_records`, `flow_work_orders`.
- **No column — global spine / shared ledger:** `identities`,
  `identity_pii`, `identity_credentials`, `identity_tokens`,
  `identity_token_revocations`, `identity_providers`, `clients`,
  `authorization_codes`, and **`states`** (the universal lifecycle
  ledger keyed by `entity_id`; org derives via `entity_id →
  entity.organization_id`. Adding org would fork the shared deleted-id
  keyspace `EntityStore.getAll` consults. The entity guard already
  hides foreign-org rows, so their state events are unreachable.).

**Classification rule for the rule-ambiguous tables** (the one open
classification — see Open Questions): a table gets the column **iff**
it is an independently-mutated, data-carrying entity the decorator must
guard directly (the decorator deliberately avoids parent lookups).
`record_attributes` qualifies (independently created/edited via
`/record-attributes/:id` + `records-multi-put`) → **column**. The
parent-dependent append-only ledgers (`flow_versions`,
`state_field_values`, `objective_revisions`,
`project_objective_baseline_scores`, `project_objective_actual_scores`)
default to **derive-from-parent (no column)** — doctrine-clean; promote
to a column only if SP-2 must facade-expose them directly. Confirm at
Phase 2.

**`role_grants` carrying org.** The column records provenance (where a
grant was made). For SP-2's single seeded org, `currentRolesFor` /
`isPermitted` (`api/authorization.ts`) stay **org-agnostic** (roles are
global capabilities — spec decision 4; the auth gate reads the base
adapter anyway). Name and defer the future seam
`currentRolesForInOrg(rows, identityId, org)` for when a second org +
a genuine per-org role requirement arrive together (Premature
Generalization avoided; the column is populated now so the data is
ready).

## Deferred / SP-boundary

- **SP-6 Identity surface** owns the `/identities` CRUD + `/pii` +
  `/providers` + `/tokens` management UI and any org-switcher console.
- **Org-aware roles** (`currentRolesForInOrg`) — named, deferred to a
  second org + a real per-org requirement. Column populated now.
- **Delegation policy** (may actor act-as subject across orgs) — the
  SP-5 server-tier seam; SP-2's facade self-delegates only.
- **Real server-held signing key** — inherited SP-3/5 constraint. The
  `org`-claim guard is only as strong as the HMAC signature
  (`access-token.ts:57`, client-shipped). Tenant isolation MUST NOT be
  relied on in a networked/multi-user context until the key is
  server-side. Restate in the `orgScopedAdapter` doc comment.
- **Cross-tab shared-write hazard** on the now-multi-row
  `organizations` table — inherits the documented `identity_tokens`
  caveat; real atomicity arrives with Postgres.
