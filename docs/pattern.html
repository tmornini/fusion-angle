How the pattern works

This page describes the mechanics of fusion-angle's storage and HTTP design and the tradeoffs the repo records. Excerpts are short quotations used to explain the design.

1. One append-only table of HTTP pairs

The table (api/schema-postgres.ts, abridged) has an envelope, the raw message bytes, and the hashes.

id uuid PRIMARY KEY,               -- also the ETag
operation_id uuid NOT NULL,        -- groups one client operation
path text COLLATE "C" NOT NULL     -- CHECK slash-bounded
name text COLLATE "C" NOT NULL,    -- '' for an operation
supersedes uuid NOT NULL,          -- the head this write follows
requester_identity_id text ...,
method text ...  CHECK (method ~ '^[A-Z]+$'),
response_at timestamptz NOT NULL,  -- the one stamp
request bytea, request_salt, request_hash,
request_secrets, request_secrets_hash,
response bytea, response_salt, response_hash,
response_secrets, response_secrets_hash,
pair_hash bytea

Indexes: (path, name, response_at, id) gives "head and history for free". (path, response_at, id) serves collections. The unique (path, name, supersedes) on PUT/DELETE rows enforces succession. path and name are separate columns, and the table holds writes only.

2. The write path: If-Match → insert with supersedes → 412

  1. The client sends If-Match: "<etag>" naming the head it read, or If-None-Match: * to declare a genesis (API.md § Conditional classes).
  2. "The gate checks presence and form, never value." A missing conditional on a required route is 428, and a malformed tag is 400.
  3. "The statement judges the value." An If-Match tag "is an in-order latch, stale unless it names the current head". The row is inserted with supersedes set to that head. A genesis supersedes the nil root.
  4. Two writers racing on the same head produce two rows with the same (path, name, supersedes), so the unique index admits only one. "A stale in-order latch is 412." "A stale latch answers 412, even for a byte-identical resend."
  5. Idempotent resends: "A resent document write whose body equals the head matches, stores nothing, and answers 200."

In the repo, all rows of one write land together in one SQL statement (api/ledger-statement-sql.ts): "Any stale row refuses the statement. Nothing is stored."

3. The read path: serve the stored response

  • Select the head with an index walk. The repo's document head is … WHERE path = $1 AND name = $2 AND method IN ('PUT','DELETE') ORDER BY response_at DESC, id DESC LIMIT 1.
  • Serve the stored bytes. Swap only the status line, date, and request-id. Add last-modified and response-at from response_at, and requester-identity-id. "The body bytes are never touched", except for read-role field projection, which happens in one function (servedResponse).
  • A collection is "multipart/mixed of application/http; msgtype=response parts, each the unit a document GET serves".
  • Store canonical bodies: the repo sorts JSON keys on write (sortJsonKeys), so byte equality means sameness.

4. History and tombstones

A version is a stored PUT pair, served at versions/:etag. Deletion appends a DELETE head, and the document then answers 410. "Document DELETE is a marked tombstone pair. No physical delete exists." Even PII erasure "appends a bodyless DELETE head; superseded PUT pairs remain in the ledger". Earlier PII versions therefore remain stored.

5. Hashing and secrets

  • Message hashes are salted SHA-256: leafHashHex(salt, bytes) (shared/pair-root.ts) hashes salt ‖ bytes, and the CHECKs require 16-byte salts and 32-byte hashes.
  • Credential header lines (authorization, cookie, set-cookie, …) are split into request_secrets and response_secrets, which are plaintext, and hashed without salt. pair_hash covers both.
  • Row integrity is "the hash tree": fa_pair_root in SQL and pairRootHex in TS. Lineage is supersedes. "No chain."

6. Tenancy in the path

"Tenancy rides path, and a membership's name. The store is global. The fence enforces organization." The organization comes from the verified token claim, and a path naming another org is 403 at the fence. "Foreign ids 404; foreign paths 403" (AGENTS.md).
